# 08 · 备份恢复与迁移

## 1. 备份容器格式（.asbk, v1）

```
┌────────────┬─────────┬────────────┬────────────────────────────┐
│ magic 4B   │ ver 1B  │ metaLen 4B │ meta JSON（明文：应用/版本/  │
│ "ASBK"     │  =1     │            │ schemaVersion/时间/长度）   │
├────────────┴─────────┴────────────┼────────────────────────────┤
│ headerLen 4B + VaultHeader（仅口令模式：KDF 参数/盐/包裹的载荷密钥）│
├───────────────────────────────────┼────────────────────────────┤
│ payload: nonce(24B) ‖ AEAD 密文（明文库文件字节）                  │
└───────────────────────────────────┴────────────────────────────┘
```

- 打开方式二选一：**DEK 直开**（本机已解锁）或**备份口令**（换机）。
- meta 与 header 是明文但**无任何秘密**（wrapped key 本身是密文）。
- 完整性 = AEAD 认证标签覆盖全部载荷；任何字节被改动 → 整体拒绝。

## 2. 导出流程

```
ATTACH '临时文件' AS exp_plain KEY '' → SELECT sqlcipher_export('exp_plain')
→ 读出明文临时库字节 → 立即删除临时文件
→ BackupContainer.create(bytes, passphrase=备份独立口令)
→ 写入用户选择的 .asbk
```

要点：
- 明文只存在于临时文件，且用后即删；
- **建议备份口令 ≠ 主口令**（一份被偷不连坐另一份）；
- 备份应保存于**独立于原设备**的位置（网盘存的是密文，但请注意 meta 里的文件名/时间属可见元数据）。

## 3. 恢复流程（隔离校验，绝不碰原库）

```
容器解密（错口令/损坏 → BackupException，原库不动）
→ 写临时明文库 → PRAGMA integrity_check + schema 版本核对
→ ATTACH '新文件' AS enc KEY x'<当前设备 DEK>' → sqlcipher_export → DETACH
→ 原库改名 .bak → 新加密库就位 → 应用锁定，重新解锁后生效
```

- 任何一步失败：原库保持原样，临时文件清理；
- schema 版本不一致 → 明确报"需要迁移"，不做有损猜测。

## 4. 换设备

1. 旧设备：导出 .asbk（备份口令）；
2. 新设备：安装 App → 创建金库（设新主口令）→ 设置页"从备份恢复"→ 输入**备份口令**；
3. 恢复后数据以**新设备 DEK** 重新加密（备份密文与设备密钥解耦）；
4. 建议立即导出一次新备份验证可读。

## 5. 密钥事件处理

| 事件 | 操作 | 数据影响 |
|---|---|---|
| 改主口令 | 设置页修改 | 无（只重包 DEK） |
| 重新生成恢复码 | 设置页 | 旧恢复码立即失效 |
| 忘记主口令 | 锁屏输入**恢复码**解锁 → 尽快改主口令 | 无 |
| 主口令+恢复码全丢 | **无法恢复**（加密数学保证） | 数据不可读——这就是离线保存恢复码的原因 |
| 疑似备份损坏 | 设置页先"校验"再决定恢复 | 校验只读，不落盘 |

## 6. 备份频率建议

- 每月复盘完成后导出一次（对应月报流程最后一步）；
- 大改动（批量导入、换设备）前后各一次；
- 至少一份离线（移动硬盘/U 盘）+ 一份异地（网盘里的密文）。

## 7. 测试覆盖

`test/security/crypto_test.dart`：口令/DEK 双模式 roundtrip、错误口令拒绝、截断拒绝、魔数破坏拒绝；`test/data`：库写入读回一致。恢复链路的端到端（sqlcipher_export）为平台能力，在真机验收清单中人工验证（docs/09 §3）。

## 8. 多设备合并（v0.14）

"从备份合并"：把另一设备的 .asbk **并入**当前账本（恢复是整库替换，合并是双向汇拢）。
适合"手机 + 电脑各自记账、网盘放 .asbk 同步"的用法。服务 `MergeService`。

### 8.1 账本谱系（防串账）

- 导出时容器 meta 写入 `vaultId` = DEK 的 SHA-256 指纹（改主口令/换恢复码不变）；
- 合并前校验：指纹不一致 → 拒绝（那是另一本账，应走"恢复"）；旧版本备份无指纹 →
  允许但红字提示人工确认；备份 schema 高于本机应用 → 拒绝（先升级）；
- 备份 schema 低于本机 → 解密后先自动迁移到当前 schema 再合并。

### 8.2 表级合并策略

| 表 | 策略 |
|---|---|
| transactions | 按 id，`updated_at` 新者胜（LWW）；分录（postings）随交易整体替换 |
| accounts / securities / budgets / goals / debt_contracts / import_batches | 按 id 补缺；本机已存在则保留本机（无时间戳，冲突罕见且可手改） |
| scheduled_events | 按 id 补缺 + 双端并存时跳过月份/日期与金额覆盖做**集合并集**（同键金额覆盖本机优先） |
| valuations | 自然键 (account_id, date, kind) 去重补缺（自增 id 不跨库） |
| fx_rates | 自然键 (base_ccy, quote_ccy, date) 去重补缺 |
| snapshots | 按月 LWW（updated_at 新者胜）——只是报表缓存 |
| settings | 只补缺；本机已有键一律保留（主题/锁时/AI 密钥是设备级偏好） |

### 8.3 安全措施

- 整个合并在**单个事务**内，任一步失败整体回滚；
- 合并前自动导出安全备份 `assetscope-premerge-<时间戳>.asbk`（DEK 模式，
  本机可随时"从备份恢复"退回合并前状态）；
- 预览先行：确认弹层逐项列出将并入的内容，两份一致时直接告知无需合并；
- 幂等：重复合并同一份备份计数为 0（LWW 等值不覆盖、补缺已完成）。

测试：`test/services/merge_test.dart`（LWW/补缺/自然键/并集/设置/幂等/谱系预检）。
