## 2. 开发规范

- **依赖方向**：domain ← data ← services ← app ← ui（见 docs/03）。PR 检查：domain 内不得 import flutter/第三方。
- **金额**：一律 `BigInt`（分）+ `Money`/`Rational`；出现 double 处理金额即 bug。
- **过账**：只经 `TxBuilders`；新增交易类型 = 新构造器 + 口径表更新 + 测试。
- **测试**：新口径必须先有测试（红）再有实现（绿）；账务规则改动必须更新 docs/05。
- **迁移**：改表 → schemaVersion+1 + MigrationStrategy 提供升级路径 + 迁移测试。
- **安全改动**：更新 docs/06 威胁模型与 MASVS 证据；密钥/口令永不写日志、示例与仓库。
- **分析**：`flutter analyze` 零 issue 是合并门槛。
- 提交信息中文/英文均可，格式：`模块: 摘要`（例：`ledger: 卖出按平均成本结转`）。

## 3. 常用命令

```bash
flutter pub get                                   # 安装依赖
dart run build_runner build --delete-conflicting-outputs  # 改表后重新生成
flutter analyze                                   # 静态检查（必须零 issue）
flutter test                                      # 单元与数据层测试
flutter run -d windows                            # 桌面运行
flutter build windows --release                   # 发布构建
```

## 4. 数据目录

- Windows：`%APPDATA%\<org>\assetscope\`（数据库 assetscope.db、密钥头 vault.key / vault.recovery.key）
- Android：应用私有目录（卸载即清空——备份的重要性）
- 密钥头文件**不含明文秘密**，但仍建议随 .asbk 一起不要放进同步网盘明文区
