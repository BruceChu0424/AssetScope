# 13 · AI 集成

> v0.4 引入 AI 行情抓取，v0.20 识别，v0.23 扩成完整 AI 子系统
> （每日资产估值 / 地址地理编码 / AI 助手 / 用量与额度）。本文件是
> AI 子系统总纲：配置模型、请求管线、能力清单、接入规范。
> 细节分工：安全边界与发送范围 → docs/06 §7；估值算法规格 →
> docs/11 §12；组件与弹层速查 → docs/12。

## 1. 总则

- **用户自带 Key，零后端**：所有 AI 请求发往用户在设置里配置的服务商
  （预设：智谱 GLM/Kimi/千问/DeepSeek/OpenAI/Claude/自定义 OpenAI 兼容
  端点）。应用本身无任何服务器。用户独占使用，无内置配额限制——
  额度即用户自己的服务商额度。
- **默认零网络**：未配置 AI 时一切 AI 能力静默降级（识别按钮提示配置、
  地理编码回退内置城市表、估值不跑、助手提示绑定）。
- **密钥安全**：AiConfig 整体（含 apiKey）存加密库 settings 表 key
  `aiProvider`；不写日志、不进明文导出（白名单排除）、异常永不回显。

## 2. 服务清单（lib/services/ai/）

| 文件 | 角色 | 关键入口 |
|---|---|---|
| ai_chat.dart | 传输层：`AiConfig`/预设表/`AiChat`（单轮 complete + 多轮 converse）、OpenAI 与 Anthropic 双协议请求构造（联网工具按预设注入） | `converse(cfg, system, messages)` |
| ai_json.dart | 结构化输出提取（```json 围栏优先，否则首 `{` 括号平衡） | `extractAiJson / decodeAiJsonObject` |
| account_ai_service.dart | 新建资产识别（名称→类型/币种/机构/城市）；地址地理编码（→WGS84 坐标） | `recognize / geocode / config` |
| quote_fetch_service.dart | 行情/汇率抓取（手动→预览→确认，docs/06 §7） | `fetch / apply` |
| ai_valuation_service.dart | 每日资产估值（docs/11 §12） | `refreshDue / refresh / estimateOne` |
| assistant_service.dart | AI 助手：多轮对话 + 账本概况汇总注入 | `reply(history:, withLedger:)` |
| ai_usage.dart | 用量按日统计（`AiUsageStore`）、计数装饰器（`CountingAiChat`）、智谱余额查询（`AiBalanceService`） | `record / fetch / parseBalance` |

providers 里统一构造一个 `CountingAiChat(onCall: aiUsage.record)` 注入
全部服务——**新增 AI 服务必须收注入的 AiChat 实例**，勿自建
`const AiChat()`，否则用量面板统计不到。

## 3. 配置模型

- `AiProviderPresets`：每预设含协议（openai/anthropic）、默认 BaseURL、
  默认模型、`supportsWebSearch`。**免费推荐=智谱 glm-4.7-flash**
  （glm-4-flash / glm-4.5-flash 已下线；配置页打开时按 dead 名单静默
  迁移，防"配置看着对、一直 404"）。
- `AiConfig` 字段：presetId/baseUrl/apiKey/model/enableWebSearch，
  JSON 存 settings `aiProvider`。各服务共用这一个绑定（读同一 key）。
- 联网搜索按预设注入（buildOpenAiMessagesRequest）：GLM=`web_search`
  工具、Kimi=`builtin_function $web_search`、千问=`enable_search`、
  OpenAI 系=`web_search` 工具；DeepSeek/自定义不注入（模型记忆数据
  需在 UI 明示可能过时）。

## 4. 请求管线与纪律

- 网络一律走 `GuardedHttp`（SSRF 守卫 + 非 2xx 解析 `error.message`、
  密钥打码，docs/06 §7）。
- **提示词必须是纯函数**（`buildXxxPrompt`）——可审计、可单测；用户
  在预览界面可见将要发送的内容。
- **结构化输出三条纪律**：①应答格式约定为严格 JSON（明确"不要
  markdown 围栏、不要解释"，但要容忍模型违规——解析走 ai_json）；
  ②查不到就 `found=false`/error 字段如实报告，**宁可不写不编数**；
  ③逐字段校验（数值为正、坐标范围、币种大写、日期解析），无效条目
  抛错或跳过并计入告警。
- **写库前用户确认**（自动任务除外）：行情/立即估值走预览→采用；
  每日估值是用户预先授权的自动任务，但写入记录可审计（source=
  `ai:<preset>/<model>`、note 留依据与来源），且同日人工纠正优先。

## 5. 能力速览

| 能力 | 触发 | 发送内容 | 结果去向 |
|---|---|---|---|
| 新建资产识别 | 表单 ✨ 按钮 | 资产名称 | 回填类型/币种/机构/城市 |
| 地理编码 | 地址输入防抖 800ms（≥4 字、未命中内置城市、已配 AI） | 地址文本 | 坐标回填（POI=准星/城市级=指南针） |
| 行情/汇率 | 用户点击 | 名称/代码 + 币种对 | 预览确认 → 估值/汇率表 |
| 每日资产估值 | 解锁后台每日一轮（用户逐资产开启） | 检索线索（名称+位置或自填） | totalValue 估值（ai: 来源，人工当日优先） |
| AI 助手 | 用户发送 | 对话 + 可选账本汇总（净资产/本月收支/支出 Top） | 聊天气泡 |
| 余额查询 | 设置面板点击 | API Key → 用户 BaseURL | 额度三行（仅智谱有公开接口） |

## 6. 用量与额度（v0.23）

- 本地统计：`AiUsageStore` 按 `aiUsage` key 存 `{total, byDay:{日期:次数}}`
  （60 天明细裁剪）；每次请求发出前计数（成败都算，经 CountingAiChat
  挂在 converse 上，complete 自动经由）。
- 服务商余额：仅智谱实现 `GET {base}/users/me/balance`（Bearer）；
  响应字段名随版本变过——parseBalance 在 data.balance / 顶层 balance /
  data 直挂三个容器里按候选键名搜（totalBalance/total、voucherBalance/
  voucher/freeBalance、cashBalance/cash），数值兼容字符串。其他服务商
  暂无公开接口，面板显示说明文字。

## 7. 新增 AI 能力 · 接入清单

1. 提示词写成纯函数 `buildXxxPrompt`（禁止内联拼在调用点）。
2. 解析用 `ai_json.dart` + 逐字段校验；遵循"查不到不编数"纪律。
3. 服务构造收 `AiChat` 依赖（providers 注入共享计数实例）；
   配置读 `aiProvider` 同一绑定。
4. 发送范围登记进 docs/06 §7 隐私边界表；涉及新表列走 schemaVersion
   +1 + 迁移测试（docs/04）。
5. UI：手动能力走 预览→确认；后台能力必须用户显式开启 + 完成通知 +
   失败静默不阻塞；错误反馈按规范（顶部通知，禁内联文字）。
6. 测试：解析纯函数单测（正常/围栏/缺字段/边界值）+ 门控与优先级
   逻辑（参考 ai_valuation_service_test 的结构）。
