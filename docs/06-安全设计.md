# 06 · 安全设计

## 1. 威胁模型

| # | 威胁 | 防护 | 残余风险 |
|---|---|---|---|
| T1 | 设备丢失/被盗 | 全库加密 + 主口令 + 自动锁定（5 分钟） | 拿到设备者可离线暴力猜口令 → 抵御靠慢哈希（见 §3） |
| T2 | 数据库/备份文件被复制 | SQLite3MultipleCiphers 全文件加密；备份为 AEAD 容器 | 同 T1 |
| T3 | 网络窃听 | 无任何联网功能（v0.1 零网络权限） | — |
| T4 | 服务器入侵 | 无服务器 | — |
| T5 | 越权/多用户 | 单用户单文件；无 IPC 暴露 | — |
| T6 | 恶意导入文件 | CSV 仅按文本解析，不执行公式/宏；行数/字段长度受限 | 阶段 2 补严格大小上限 |
| T7 | 第三方（云/AI）泄露 | 默认不外发任何数据 | — |
| T8 | 键盘记录器/被植入的宿主 | **不在防护范围**（诚实声明） | 若设备已被控制，任何本地加密均无意义 |

## 2. 密钥层级（KEK/DEK 分离）

```
主口令 ──KDF(慢哈希+盐)──▶ KEK（仅存于内存）
                              │ AEAD 包裹
随机 32B DEK ────────────────▼──▶ VaultHeader{salt, kdf参数, wrappedDek}（明文文件，无秘密）
   │
   ├─▶ PRAGMA key = x'<DEK hex>'   （数据库密钥，SQLite3MultipleCiphers）
   └─▶ 备份容器载荷密钥（或备份独立口令另包一份随机载荷密钥）
```

- **改口令 = 只重包 DEK**，数据库与备份不需重加密。
- **恢复码** = 第二个口令（独立盐与头文件 `vault.recovery.key`），丢失主口令的唯一自救；重新生成即作废旧码。
- 头部内嵌 KDF 算法与参数（算法敏捷）：`pbkdf2-hmac-sha512` / `argon2id` 互通，升级不丢数据。

## 3. 密码学选择

| 用途 | 默认（DartCryptoSuite） | 升级（SodiumCryptoSuite，已实现待启用） |
|---|---|---|
| KDF | PBKDF2-HMAC-SHA512，600,000 轮（OWASP 2023 建议量级） | **Argon2id**（opsLimit/memLimit moderate，内存困难） |
| AEAD | XChaCha20-Poly1305（24B 随机 nonce） | XSalsa20-Poly1305（secretBox） |
| 随机 | Random.secure（平台 CSPRNG） | libsodium randombytes |

- 认证加密覆盖**全部密文**：错口令、篡改、截断一律整体拒绝，绝不部分解密。
- nonce 每次 24B 全随机；单密钥下 2³² 次封装箱内生日碰撞概率 ≈ 2⁻⁶⁴（个人账本生命周期内安全）；换口令/换 DEK 后密钥全新，无 nonce 复用面。
- **KDF 与全部密码学不落入 double**；测试套件钉死"错口令必拒、篡改必拒、头部无 DEK 明文"。

## 4. 数据库加密

- 引擎：SQLite3MultipleCiphers（pubspec `hooks.user_defines.sqlite3.source: sqlite3mc`，sqlite3 3.x build hook）。
- 打开：`NativeDatabase.createInBackground(..., setup: PRAGMA key = "x'…'")` —— key 先于一切访问。
- WAL/journal 由加密引擎一并加密；未设置 key 时**拒绝打开财务库**（fail-closed）。
- 校验：`PRAGMA cipher` 非空（构建变体自检，防"静默明文"事故——drift 社区已知坑）。

## 5. 锁定与会话

- 任何指针活动重置 5 分钟计时；到点：关库 → DEK 置 null → 路由回锁屏。
- Dart 无法保证内存清零（GC 语义）——诚实限制：锁定后至进程结束前，内存中可能残留密钥副本；缓解=锁定即关库，后续任何访问都需重新派生。

## 6. 备份（详见 docs/08）

- 明文只存在于临时文件，容器化后立即删除；
- 恢复在隔离临时库上校验（integrity_check + schema 版本），通过后以**新 DEK** 重新加密替换，原库留 `.bak`；
- 失败路径不动原库（测试钉死）。

## 7. AI 能力出网与流量边界（v0.4 行情；v0.20 识别；v0.23 估值/定位/助手/额度）

> AI 子系统总纲（服务清单/配置模型/接入规范）见 docs/13-AI集成.md。

默认**零网络**。出网分两类：**用户当场触发**（行情抓取/名称识别/地理编码/立即估值/AI 对话/余额查询）与**用户预先授权的后台任务**（每日 AI 资产估值——仅对用户逐个开启了「每日 AI 估值」开关的资产，每天首轮解锁后执行一次；随时可在账户详情关闭）。边界如下：

- **密钥存放**：AI API Key 存加密库 settings 表（key `aiProvider`），随整库加密；不写日志、不进备份明文、异常信息永不回显 Key。直连行情源**无需任何密钥**。
- **发送范围（隐私边界，按能力划分）**：
  - 行情/汇率（v0.4）：只发送持仓**名称或证券代码**与币种对（如"600519"、"USD/CNY"）。
  - 新建资产识别（v0.20）：只发送资产**名称**。
  - 地理编码（v0.23）：只发送用户输入的**地址文本**（转经纬度用）。
  - 资产估值（v0.23）：只发送**估值检索线索**（名称+位置或用户自填的小区/年款信息）——绝不发送购置成本、金额、账户编号、交易流水。
  - AI 助手（v0.23）：发送**对话内容**；「账本概况」开关（默认开）额外注入净资产/本月收支/支出 Top 等**汇总整数**——不含逐笔明细、不含账户编号。用户可一键关闭退回纯通用对话。
  - 余额查询（v0.23）：仅智谱实现了公开接口（`GET {base}/users/me/balance`），只发送用户自己的 API Key 到其配置的 BaseURL。
  - 所有提示词由纯函数生成（buildXxxPrompt），可审计；直连行情端点为固定域名。
- **直连源端点（v0.6）**：腾讯行情 `qt.gtimg.cn`（A股/场内基金，GBK）、stooq `stooq.com`（港股/美股/国际，CSV）、frankfurter `api.frankfurter.dev`（欧央行参考汇率，JSON）。均免费无 key；域名硬编码不可被用户输入注入；同样经过出网守卫。
- **出网守卫（SSRF 防护，v0.22 攻防加固）**：`services/net/guarded_http.dart` 仅允许 http/https；拒绝 localhost / *.local / *.internal（云元数据域）/ 环回 / 私有（10/8、172.16/12、192.168/16）/ 链路本地 / 保留 / 组播地址（IPv4+IPv6，含 mapped）。**IP 编码绕过全拦**：十进制整数主机（2130706433=127.0.0.1）、十六/八进制段（0x7f.0.0.1 / 0177.0.0.1）、超界段（999.1.1.1）、userinfo 混淆（good.com@10.0.0.1）。**重定向每跳校验**：手动跟随（≤5 跳），每一跳的 Location 目标都过同一守卫（防公网端点 302 跳内网/云元数据）；**跨主机跳转剥离 Authorization/x-api-key**（防 key 被中继到第三方）。**错误信息脱敏**：非 2xx 异常只含状态码 + 响应体摘录（优先 error.message），且对请求头值与裸 token 全量打码——恶意端点回显密钥也不会进 UI/日志（guarded_http_test + guarded_http_adversarial_test 钉死）。
- **数据可信度**：直连源为官方行情端点（一手数据），AI 返回的是**二手行情**。两种模式统一逐条预览（价格、日期、来源、币种一致性核对——直连按市场推断币种：A股=CNY、港股=HKD、美股=USD）→ 用户确认 → 才写入；写入记录 source=`direct` 或 `ai:预设/模型`、note 保留来源，与手工录入可区分、可审计。解析失败/查不到→不写库，宁可没有不编造。
- **后台行为（v0.23 修订）**：唯一的后台出网是**每日 AI 资产估值**——前提是用户对具体资产开启了「每日 AI 估值」（新建表单默认勾选，可关），且已配置 AI；每天最多一轮（settings `aiValuation.lastRunDay` 门控），只对开启估值的资产发送检索线索，结果写入可审计的估值记录（source=`ai:预设/模型`）；**当日用户手动改过估值的资产自动跳过**（人工纠正优先）。用户在同日内改主意可关开关，此后不再出网。其余 AI 能力（行情/识别/定位/对话/余额）仍全部为用户当场点击触发。

## 9. 已知限制（诚实清单）

1. sodium 原生套件未默认启用（等各平台构建验证），当前 KDF 为 PBKDF2-SHA512-600k——强度可接受但非内存困难。
2. 内存清零受 Dart 运行时限制（§5）。
3. 无防截屏/通知脱敏（移动端阶段 2）。
4. 恢复码与主口令同时丢失 = 数据不可恢复（数学事实，不承诺谎言）。
5. 未做正式第三方安全审计；以上为实现与测试层面的验证。
