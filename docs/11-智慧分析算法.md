# 11 · 智慧分析算法

v0.2 引入的"智慧层"：全部为**纯 Dart 领域代码**（`lib/domain/analytics/`），
不依赖 Flutter/第三方，金额全 BigInt，比率仅展示用 double。
组装层为 `lib/services/insight_service.dart`。测试见 `test/domain/analytics_test.dart`。

## 1. 消费配速预测（spending_pace.dart）

问题：月中看预算只知道"已花多少"，不知道**按当前速度月末会花多少**。

口径：

```
日均速度 v = 已花 / 已过天数（首日计 1 天）
月末预测 P = 已花 + v × 剩余天数
剩余日均可花 = max(0, (额度 − P) / 剩余天数)
```

整数除法（BigInt `~/`）保证不出现分币；`overPace = P > 额度`。
注意：预测不扣除固定计划占用（计划占用在预算信封中单列披露，避免双重扣减）。

## 2. 周期交易识别（recurring_detector.dart）

问题：房租、订阅、工资这类周期流水，用户往往重复手工记账而不是建计划。

算法：按 `(对手方, 方向)` 分桶 → 计算相邻间隔序列 → **间隔中位数 ±3 天**
（覆盖 31/30 天月差与周末漂移）内的比例 ≥ 70% 判定为周期 → 金额稳定性
（最大偏差 ≤ 中位数 10%）与样本量共同给出置信度：

```
confidence = 规整度 × 金额稳定度(1.0 或 0.6) × min(1, n/6)
```

约束：≥3 次观测；间隔 <5 天视为噪声；断档超过 2 个周期不再建议。
产出可直接转 `ScheduledEvent` 草稿（`nextExpected` 处理跨月推算）。

**固化为计划（v0.3）**：`planCadence(now)` 把间隔桶映射到计划周期
（350–380 天→每年；28–32→每月；13–15→双周；6–8→每周；其余→自定义间隔天数），
锚点日 = `nextExpected(now)`，金额 = 中位数。计划页"从流水识别固定收支"
弹层列出建议，一键带预填值打开计划编辑对话框；同名计划已存在则标注"已建计划"。

为何用中位数而非均值：补记、跳月等个别异常点不会把基线拉歪。

## 3. 异常消费检测（anomaly.dart）

问题：哪个分类本月"不对劲"？规则阈值（如 >20%）对不同量级分类不公平。

算法：每分类近 5 个月（不含本月）支出 → 中位数 M 与 **MAD（绝对中位差）** →
稳健 z 分数：

```
z = |本月 − M| / (1.4826 × MAD)
```

1.4826 是 MAD→标准差的一致性常数。MAD=0（完全稳定序列）时退化为相对偏差
dev/M。z ≥ 3 报警，`spendUp` 区分激增/骤降。单月历史大额（年缴保费）
不会污染基线——这正是中位数系统计的性质（测试覆盖）。

## 4. 财务健康与里程碑（health.dart）

四个指标（`computeHealth`，除零一律 null 而非假 0）：

| 指标 | 口径 |
|---|---|
| 储蓄率 | (收入−消费)/收入（本月常规收支） |
| 应急月数 | 流动资产(变现≤30天) / 近 3 个月月均消费 |
| 资产负债率 | 总负债/总资产 |
| 固定收支覆盖比 | 月固定计划收入/月固定计划支出（<1 即结构性缺口） |

**净资产里程碑预测**：Theil–Sen 稳健回归 = 所有点对斜率的**中位数**。
对"一次性大额支出月"免疫（测试：6 个月序列含一个暴跌月，斜率仍≈真实趋势）。
目标是"下一个整数关口"（<100 万按 10 万步进，之后按 100 万）；
趋势不向上或 >60 年不可达返回 null（诚实地说"算不出来"）。

## 5. 商户→分类规则引擎（domain/import/category_rules.dart）

三级匹配（置信度递减，**只建议不强制**）：

1. **显式关键词规则**（用户管理，JSON 持久化于 settings 表 `categoryRules`），
   最长关键词优先（"美团外卖" > "美团"）；
2. **历史精确对手方**：同名对手方过往分类的多数投票，置信度=占比（下限 0.5）；
3. **历史模糊对手方**：最长公共子串 ≥2 字符（中文单字太泛），封顶 0.85——
   模糊建议永远低于精确。

学习是**自动且无副作用**的：引擎每次导入前从全量流水重建频率表
（`InsightService.buildRulesEngine`），用户改判后的下一轮自然生效。

## 6. 投资组合收益：XIRR + TWR（insight_service.portfolioReturns）

组合边界 = 券商现金 + 全部持仓账户。三类事件的处理：

| 事件 | 处理 |
|---|---|
| 买入/卖出/分红 | 组合内部事件，**不是**现金流 |
| 跨边界转账（银行→券商等） | 投入为负（钱进入组合） |
| 期末 | 当前组合市值（含券商现金）作为回收 |

XIRR 本体（牛顿 + 二分兜底，docs/05 §6）位于 `domain/invest/returns.dart`。
外币流水按交易日前最近汇率折算；缺历史汇率的整笔**跳过并计数披露**
（宁可少算不乱算）。

**TWR（v0.3 接入）**：取近 13 个月末 + 今天共 14 个候选估值点；某时点
任一在持仓缺价（或外币缺汇率）则该点整体作废——绝不"缺价计 0"污染期间收益。
有效点 <2 时 TWR 为 null（界面只显示 XIRR）。这与 XIRR 的哲学一致：
TWR 剔除资金进出时点的影响，衡量标的表现；XIRR 含加减仓时点影响，
衡量真实到手收益。两者并列展示（投资组合卡），口径见 docs/05 §6。
估值点充足的前提是**持仓逐月有估值记录**——月度维护估价的用户才享有 TWR。

## 7. 还款策略对比（domain/debt/debt_contract.dart 的 DebtPayoffPlanner）

v0.1 已实现，v0.2 接入 UI：给定各负债（剩余本金、APR、最低还款）与
每月额外还款额，逐月模拟"先付各笔最低 → 额外资金按策略注入 →
还清一笔后其最低还款滚入资金池"。雪崩=高利率优先；雪球=小额余额优先。
输出期数、总利息、还清顺序与两策略利息差。

## 8. 组装与展示（InsightService.dashboardInsights）

一次调用聚合：体检四指标 + 配速 + 异常 top2 + 周期建议 top2 + 里程碑，
并产出面向用户的洞察文案（如"应急准备金 ≈ 4.2 个月，低于 3 个月基本线…"）。
文案规则：数字先行、给行动建议、不做道德评判。

## 9. 3D 资产地球（lib/ui/globe/）

不算"算法"但属于智慧层的一部分：

- 数据：Natural Earth 110m 海岸线（公有领域）→ 斐波那契球面 26,000 均匀采样点
  → 射线法保留陆地点 7,498 个 → `assets/globe/land_dots.json`（92KB，全离线）。
- 渲染：`CustomPainter` 正交投影；陆地按深度（z）渐隐、经纬网 30°、
  资产标记呼吸光圈（相位错开防同步闪烁）、大小按 √价值 缩放。
- 交互：拖拽（灵敏度随缩放）+ 惯性衰减 + 空闲 4s 自转；点击命中测试 →
  最短经度路径飞行 650ms → 详情弹层。坐标存账户表 v2 字段（lat/lon/name），
  提供城市快选（内置 58 城坐标）。

## 10. 设计原则（本层所有算法）

1. **稳健优于聪明**：中位数/MAD/Theil-Sen 而非均值/方差/OLS——个人账本
   必然有离群月（年缴、大额、补记）。
2. **诚实的不确定性**：除零、样本不足、趋势向下 → 返回 null 并在 UI 显示"—"，
   不给假 0。
3. **建议不强制**：周期建议、分类建议、策略对比都是"可采纳的洞察"，
   永不自动改账。
4. **金额 BigInt，比率 double 仅展示**：与全项目口径一致（docs/05）。


## 11. 个人消费指数"我的通胀"（v0.11，domain/analytics/personal_cpi.dart）

统计局 CPI 是平均人的篮子；这里用账本自己的分类支出构造**固定篮子
Laspeyres 近似**："维持基期消费结构不变，现在要多花多少"。

- **窗口**：取近 12 个月，前 6 个月为基期、后 6 个月为近期；两侧各按
  **月均支出**比较（月均 = 窗口合计 ÷ 月数，金额 BigInt 精确）。
- **篮子**：基期各消费分类的月均支出份额 wᵢ；指数 = Σ wᵢ×(近期月均ᵢ/基期月均ᵢ)。
- **边界**：基期有、近期归零的分类（消费习惯消失）剔除出篮子并对剩余权重
  归一；基期没有、近期新增的分类天然不在篮子——两者以 basketCoverage
  （可比较权重和）披露，<0.6 标记不可靠。样本 <6 个月或基期全零 → null。
- **年化**：指数^(12/间隔月) − 1（间隔 = 近期窗末 − 基期窗首的月差；
  double 仅出现在比率空间）。贡献分解 = wᵢ×(ratioᵢ−1) 降序（UI 取前三）。
